# Project Context & Architecture

## System Architecture

OrangeNote is a native macOS desktop application built with SwiftUI and Rust (via a C FFI interface). It is NOT a Tauri or Electron application.

```
[ TranscriptionView ]
       │
       ▼
[ TranscriptionViewModel ]
       │
       ▼
[ OrangeNoteEngine ]
       │  (C ABI / orangenote_ffi.h)
       ▼
[ orangenote-ffi ]
       │
       ▼
[ WhisperTranscriber ]
       │
       ├──► [ AudioProcessor ]
       └──► [ whisper.cpp ]
```

### Core File Paths & Topology

- **UI Layer (SwiftUI)**:
  - `OrangeNote/Views/TranscriptionView.swift`: Main transcription user interface, model selector, file selection, and progress views.
  - `OrangeNote/Views/Components/FileDropZone.swift`: Visual drop zone handling file drag-and-drop operations.
  - `OrangeNote/Views/ResultsView.swift`: Transcript inspection, segment table, and export triggers.
- **State & ViewModel Layer (Swift)**:
  - `OrangeNote/ViewModels/TranscriptionViewModel.swift`: Single-file transcription state management (`ObservableObject` with `@Published` properties) and engine coordination.
  - `OrangeNote/Models/AppState.swift`: Global application state holding active in-memory `TranscriptionResult` and menu command triggers.
- **Bridge Layer (Swift / C FFI)**:
  - `OrangeNote/Bridge/OrangeNoteFFI.swift`: Swift wrapper (`OrangeNoteEngine` instantiated per use) calling C ABI functions and receiving progress callbacks.
  - `OrangeNote/Bridge/FFITypes.swift`: Swift struct definitions bridging C JSON return structs to native models.
  - `orangenote-ffi/include/orangenote_ffi.h`: Exported C ABI headers generated by cbindgen.
- **Rust Backend Layer**:
  - `orangenote-ffi/src/lib.rs`: Rust FFI entry points (`orangenote_transcribe_file`, `orangenote_transcribe_file_chunked`, model management, progress callback forwarders).
  - `orangenote-core/src/infrastructure/transcription/whisper/transcriber.rs`: High-level Whisper engine orchestrating audio decoding and whisper.cpp inference.
  - `orangenote-core/src/infrastructure/audio/processor.rs`: Audio loading, normalization, channel mixing, and 16kHz resampling.

## Verified Baseline Facts

1. **Local Whisper Engine Workflow**: Single-file local Whisper transcription pipeline is the existing functional architecture with progress reporting and segment generation.
2. **ViewModel State**: `TranscriptionViewModel` is an `ObservableObject` managing `@Published var selectedFileURL: URL?`, `@Published var isTranscribing: Bool`, `@Published var progress: Float`, `@Published var result: TranscriptionResult?`, `@Published var errorMessage: String?`, and `@Published var statusMessage: String`.
3. **Drop Zone View Lifecycle**: Drag-and-Drop is attached to `FileDropZone`, which is conditionally removed from the view hierarchy once `selectedFileURL` is populated. As a result, users cannot drag a replacement audio file without clearing the existing selection first.
4. **Task Cancellation Boundary & Race Conditions**: Swift `Task.cancel()` does not interrupt blocking Rust C FFI execution once `orangenote_transcribe_file` has been entered. Because cancellation does not stop the background FFI thread, a late completion can currently update UI state unexpectedly; explicit `jobID` validation guards are required to discard stale results.
5. **JSON Schema Incompatibility**: The JSON schema exported by Rust/FFI (`FFITranscriptionResult` / `FFITranscriptionSegment` with `start_ms`, `end_ms`, `confidence`) differs from the Swift `Codable` serialization used in `TranscriptionImportService` and `ExportViewModel` (`startTime`, `endTime`, `fullText`), causing incompatibility between exported files and the import parser.
6. **App Sandbox Entitlements**: The application is sandboxed (`com.apple.security.app-sandbox` = true) with `com.apple.security.files.user-selected.read-only` and `com.apple.security.network.client`. Batch output writing requires updating user-selected file permissions to `com.apple.security.files.user-selected.read-write` (not both read-only and read-write).
7. **In-Memory Results & AppState Mirror**: `ResultsView` operates purely on the active in-memory `TranscriptionResult`. `AppState` mirrors the current transcription result for menu commands (Save, Export). There is no persistent database or historical transcript storage.
8. **Absence of Legacy Features**: There is currently no persistent database, no historical transcription store, no generic multi-engine protocol, no Gemini cloud transcription integration, and no batch processing engine.
